## 使用说明

1. 将 **「完整 Prompt」** 整段复制到 AI 工具中。
2. 固定文案须与需求文档 **逐字一致**；组件尺寸与命名尽量沿用冷淡风 MVP 规范。

## 全局导航（Tab A，已选定）

本方案采用 **底部 Tab Bar**，四个根级页面 **无返回**；从根页进入 **子页面**（如衣物详情、我的模特）时 **HeaderBar 显示返回**。

| Tab 顺序 | 标签 | Screen | 说明 |
|---------|------|--------|------|
| 1 | 首页 | `Screen/Home` | 根页，无返回 |
| 2 | 衣橱 | `Screen/Wardrobe` | 根页，无返回 |
| 3 | 工坊 | `Screen/Workshop` | 根页，无返回 |
| 4 | 我的 | `Screen/Profile` | 根页，无返回 |

- **Tab Bar**：高度约 `56px`；选中态 `Color/Accent`，未选中 `Color/TextSecondary`；背景与 `Color/Card` 或 `Color/Background` 全 App 统一。
- **子页返回**：从某一 Tab 根页 `push` 子页时，子页 `HeaderBar` 左侧返回，回到 **发起该子页的 Tab 根页**。
- **「我的穿搭」入口（方案 B，已选定）**：**仅**在 **`Screen/Profile`** 中提供常驻列表项 **`我的穿搭`**，进入 **`Screen/Looks`**。**不在** `Screen/Workshop` 顶栏增加「我的穿搭」常驻入口。保存搭配成功后的 **`查看我的穿搭`** 为一次性快捷入口，与常驻入口指向同一 `Screen/Looks`。
- **「我的穿搭」返回栈**：从 **`Screen/Profile` → `Screen/Looks`** 时，返回 → **`Screen/Profile`**。从 **`Screen/Workshop`** 经保存成功后的 **`查看我的穿搭` → `Screen/Looks`** 时，返回 → **`Screen/Workshop`**。

## 「我的」主页（Screen/Profile）结构摘要

- **定位**：个人中心 = 模特入口（需求 2）+ **穿搭记录入口**（**`我的穿搭`** → 需求 19–20）+ **设置**中的 **`查看新手教程`**（NFR-5）。
- **根页行为**：标题逐字 **`我的`**；**无**左侧返回（与 Tab A 一致）。
- **建议分区**：
  1. **模特摘要卡** `Comp/Profile/ModelSummaryCard`：未设置时副文案逐字 **`点击设置您的模特`**，点击 → `Screen/Model/Setup`；已设置点击 → `Screen/Profile/MyModel`。
  2. **列表行** **`我的模特`**：与摘要卡二选一重复或并存（若并存则跳转目标与摘要卡一致）→ `Screen/Profile/MyModel`。
  3. **列表行** **`我的穿搭`**（方案 B **唯一常驻入口**）→ `Screen/Looks`。
  4. **设置**：一行 **`查看新手教程`** → `Screen/Onboarding`（可复用引导页）。
- **列表自上而下顺序（已定）**：在「我的模特」相关区块之后、**「查看新手教程」之前** 放置 **「我的穿搭」** 一行（即 **我的穿搭** 紧挨在 **新手教程** 上方，二者勿颠倒）。
- **子页** `Screen/Profile/MyModel`：标题可用 **`我的模特`**；**有返回**；大图 + 按钮 **`更换模特`**；后续 Dialog/Toast 文案见完整 Prompt。

## 产品决策补充（原不明确项，已收敛）

以下条目用于补齐需求文档未写死的 **信息架构 / 交互**；与 EARS 验收不冲突处已给 **默认方案**（便于直接生成界面稿）。**首页主区布局**若与产品最终不一致，仅需替换完整 Prompt 中 **D 节**对应段落。

### 1 冷启动与首次模特

- **引导页**（3–5 页）→ 用户可 **跳过** → 进入 **`Screen/Home`**（Tab「首页」）。
- **模特**：允许 **跳过**（需求 1）；跳过后使用默认占位图，并在首页展示提示条 **`点击设置您的模特`**，且可在 **`Screen/Profile`** 中管理。
- **已定稿**：引导结束默认进入 **`Screen/Home`**；不强制先进入模特设置页。模特通过首页提示条 **`点击设置您的模特`** 或 `Screen/Profile` 入口补设。

### 2 首页与底栏（Tab A）（**已定稿**）

| 方案 | 内容 |
|------|------|
| **采用（产品已确认）** | **`Screen/Home` 主区保留 3 个入口**：1) 居中大卡片 **`试穿新衣`**（主入口）2) **`我的衣橱`** 入口 3) **`穿搭工坊`** 入口；同时保留底栏 Tab 导航（首页中的衣橱/工坊入口作为快捷入口） |

- 首页入口布局细则：`试穿新衣` 使用更强视觉层级（大卡片、主按钮样式），`我的衣橱` 与 `穿搭工坊` 为次级入口（小卡片或并排按钮）。

### 3 账号与数据（MVP）

- **无登录、无账号中心**；需求未要求用户体系，界面 **不提供** 注册/登录/个人资料（除模特与本地记录外）。
- **隐私与存储**与 NFR-3 一致：模特与生成结果以 **本机** 为主；网络权限说明文案按需求固定表述。

### 4 更换模特后批量重算失败（需求 2 / NFR-2）

- **已定**：批量过程中若出现失败，**仅**使用 Toast：**`部分衣物更新失败，可稍后重试`**。
- **不做**单独「失败列表」页或底部 Sheet 逐条重试（MVP）；后续若需满足 NFR-2「单独重试」的完整交互，再增加失败列表与 **`Screen/Wardrobe` 内单件重试** 等扩展。

### 5 权限与「前往设置」

- **相册读**（试穿选图）、**相册写**（保存搭配图）拒绝时：**统一**使用 `Comp/Feedback/Dialog`（或底部 Sheet），**固定文案**以需求为准；**前往设置** 跳转系统设置（原型标注即可）。
- 同类弹窗 **视觉与按钮结构全 App 统一**，避免每页一套样式。

### 6 边缘情况（EC-3 衣橱数据 / 回收站）

- **数据损坏 / 修复 / 重置**：以 **按需弹出的 Dialog 或全屏状态** 呈现，**不**要求单独常驻「关于」页；文案逐字遵循 EC-3（含 **联系客服** 入口，可为占位按钮或外链）。
- **回收站（24 小时内恢复）**：**暂不纳入 MVP 首发**，调整为 **Phase 2**。MVP 删除流程不提供恢复入口；若后续启用，再增加 **`Screen/Wardrobe/RecycleBin`** 与入口。

### 7 首次功能引导气泡（NFR-5，已定稿）

- **覆盖范围（最小版 3 处）**：
  1) `Screen/Home`：试穿入口引导；
  2) `Screen/Wardrobe`：衣橱空状态引导；
  3) `Screen/Workshop`：工坊空状态引导。
- **出现频次**：每个引导气泡仅出现 **1 次**（once-only）。
- **不纳入首版**：结果页手势引导、我的页入口引导等扩展气泡（后续版本按需追加）。

### 8 异常退出后状态恢复（NFR-2，MVP 已定稿）

- 采用 **最小恢复策略**：仅恢复试穿链路，不恢复复杂编辑态。
- **恢复范围**：选图后处理中 / 生成中 / 生成完成但用户未离开结果页。
- **不恢复范围**：工坊多件组合过程、筛选面板展开态、编辑表单未保存内容。
- 下次启动若检测到可恢复状态，弹窗提示：**`检测到上次未完成试穿，是否继续？`**（按钮：`继续` / `取消`）。
- 当用户选择 **继续**：回到对应试穿状态页；当用户选择 **取消**：清理临时状态并进入 `Screen/Home`。

## 完整 Prompt

```text
你是一位资深移动端 UI 设计师。请根据以下两份资料生成「手机端 APP 界面设计指令（多页面）」，用于 AI 生成界面原型（可理解为：给 UI 生成器/画 Figma 原型用的 Prompt）。
资料来源：
- 产品需求与验收：衣橱EARS需求文档（AI穿搭助手）
- 冷淡风 MVP 视觉与组件规范：MVP_界面方案_冷淡风

输出要求：
1) 只输出界面与交互指令，不输出任何代码实现细节。
2) 所有「固定文案」必须逐字一致，按钮/提示/空状态/弹窗标题等不得擅自改字。
3) 每个页面都要写清：画板尺寸、布局结构、关键组件、关键状态（loading/empty/error/dialog/toast）、以及「当...时，界面应...（显示/弹出/跳转）」的交互逻辑。
4) 统一使用冷淡风规范的 Tokens 与组件命名方式（尽量沿用组件路径与参数）。页面 Frame 尺寸统一为 390x884，内容左右 padding 16px。
5) 适配 iOS/Android：视觉与功能一致；375px~428px 宽度自适应；在低性能设备可降图片加载质量以保持流畅。

通用风格与组件约束（必须遵循）：
- Frame 尺寸：390x884
- 背景：Color/Background
- 左右 padding：16px
- 可复用组件优先使用 Tokens 与现成命名组件：
  - Comp/Buttons/Primary44（主按钮：高度 44，圆角 12，填充 Color/Accent，Text/Button16）
  - Comp/Buttons/Secondary44（次按钮：高度 44，圆角 12，边框 1px Color/Accent，文字 Color/Accent，Text/Button16）
  - Comp/Navigation/HeaderBar（顶部栏：返回/标题/可选右侧空占位，高度建议 56）
  - Comp/Lists/EmptyState（空状态：居中、内含 EmptyIllustration/EmptyTitle/EmptyBody/EmptyCTA）
  - Comp/Feedback/Toast（轻提示：2 秒后自动消失）
  - Comp/Feedback/Dialog（中心弹窗通用确认/权限弹窗）
  - Comp/Feedback/OverlayLoading（全屏加载遮罩：Spinner + LoadingText，叠加不同文案）
  - Comp/Action/FloatingActionBar3（试穿结果页底部悬浮 3 按钮栏：Bottom pin + 卡片样式、阴影）

交互/状态通用规则：
- 所有异步操作使用 overlay 或 loading：API 请求中用全屏遮罩或对应 Loading 页面。
- 网络不可用时：显示「网络不可用」，并允许继续浏览已缓存的衣橱内容（在相关页面描述「缓存可用时的降级显示方式」）。
- 所有「保存/删除/批量更新失败」等成功或失败反馈用 Toast：按需求文档指定的固定文案。
- 当需要从一个页面跳转到另一个页面时，用「跳转到 Screen/... 页面」的方式明确路径。

全局导航（Tab A，必须遵循）：
- 应用外壳使用底部 Tab Bar：从左到右四个 Tab，标签文案依次为「首页」「衣橱」「工坊」「我的」，对应 Screen/Home、Screen/Wardrobe、Screen/Workshop、Screen/Profile。
- Tab 根级页面（上述四页）的 HeaderBar 不显示左侧返回按钮；仅依赖系统手势按平台规则退出应用（不在界面内绘制「退出 App」按钮）。
- 从任一 Tab 根页进入子页面（如 Screen/Profile/MyModel、Screen/Wardrobe/Detail、Screen/Looks、Screen/Looks/Detail）时，子页面 HeaderBar 显示返回：返回到 **入栈时的上一页**（通常为对应 Tab 根页；特例见下条）。
- Screen/Looks（我的穿搭列表）：若从 Screen/Profile 进入，返回 → Screen/Profile；若从 Screen/Workshop 经保存成功后的「查看我的穿搭」进入，返回 → Screen/Workshop（方案 B：工坊无其它常驻「我的穿搭」入口）。
- Tab Bar 组件可命名为 Comp/Navigation/TabBar；单 Tab 为 TabItem（图标+文字标签）；高度约 56px；选中态 Color/Accent，未选中 Color/TextSecondary；背景与 Color/Card 或 Color/Background 全应用统一。
- 切换 Tab 时保留各 Tab 根页滚动位置（原型说明即可）。

- 当穿搭记录为空：
  - 显示文案：暂无保存的搭配，去穿搭工坊创建一个吧
  - 提供 CTA：去搭配
长按菜单：
- 当用户长按某条记录：
  - 显示快捷操作菜单：编辑、删除、分享
  - 对每项操作给出「跳转/弹窗」的原型说明：
    - 编辑：进入详情后「再次编辑」或进入工坊并加载该搭配
    - 删除：显示确认弹窗（按钮可使用 取消 与 确认删除 风格一致），删除成功后 Toast：已删除
    - 分享：复用工坊分享逻辑（展示分享面板，保存图片/权限错误文案沿用 需要相册权限以保存图片）

00N. 穿搭记录详情与再次编辑
Screen：Screen/Looks/Detail
布局：
- 顶部：HeaderBar（可返回）
- 主区：完整搭配图
- 下方/列表：包含的衣物列表
  - 每件衣物显示缩略图与名称
交互逻辑：
- 当用户点击某件衣物缩略图：
  - 跳转至对应衣物详情页 Screen/Wardrobe/Detail
- 当用户点击 再次编辑 按钮：
  - 跳转到 Screen/Workshop
  - 并自动加载该搭配中的所有衣物
缺失处理：
- 当用户在编辑前发现原搭配中部分衣物已被删除：
  - 提示：原搭配中的部分衣物已被删除
  - 并显示缺失衣物的信息（缺失项可用占位「已删除」样式，不要擅自新增文案到固定句子之外）

O. 全局非功能性需求的界面体现（必须在对应页面说明）
P1 性能与首屏：
- 当用户进入试穿流程：
  - 在 3 秒内展示上身效果图（Prototype 用 loading 逻辑与时间阈值说明）
- 当 API 响应慢：
  - 使用加载动画与文案切换（已在 Screen/TryOn/Loading 体现）
- 当衣橱加载：
  - 首屏 1 秒内显示内容（用低分辨率占位图，随后替换高清图的说明写清楚）
P2 容错与网络：
- 当 AI 试穿 API 调用失败：
  - 走 Screen/TryOn/Error 并显示：生成失败，请稍后重试
- 当网络断开：
  - 显示提示：网络不可用
  - 并允许用户继续浏览已缓存的衣橱内容（在 Screen/Wardrobe 的描述中加入「离线可浏览缓存列表」的原型说明）
- 当批量操作部分失败（如更换模特后批量重算）：
  - MVP：仅 Toast「部分衣物更新失败，可稍后重试」，不单独做失败列表/逐条重试界面；与「产品决策补充」第 4 条一致
- 当应用异常退出：
  - MVP 仅恢复试穿链路（处理中/生成中/结果未离开）；启动时提示「检测到上次未完成试穿，是否继续？」（继续/取消）
P3 隐私保护（界面文字与权限解释）：
- 当请求网络/权限相关时（尤其相册权限）：
  - 说明仅用于 AI 试穿 API 调用，不用于数据存储
- 试穿生成的结果、模特与搭配数据应仅在本地保存
P4 兼容性：
- 适配 375px~428px 宽度
- iOS/Android 功能一致
P5 存储空间不足：
- 当设备存储空间不足时：
  - 提示：存储空间不足，请清理部分数据
P6 易用性与新手教程：
- 首次启动：引导页 3-5 页（见 A）
- 用户可跳过并进入应用
- 首次功能引导气泡采用最小版 3 处（Home 试穿入口 / Wardrobe 空状态 / Workshop 空状态），每个气泡仅出现 1 次
- 引导完成后，在 Screen/Profile 提供入口：查看新手教程（见 C 节；不要求单独 Screen/Settings，除非产品扩展）

P7 衣橱数据异常与回收站（EC-3，界面按需出现）：
- 当检测到衣橱数据损坏：全屏或 Dialog，文案「数据异常，正在尝试恢复」；修复失败后 Dialog「数据恢复失败，是否重置衣橱？」并提供「联系客服」（占位或外链）。
- 回收站：MVP 暂不纳入首发，调整为 Phase 2（当前版本不提供回收站入口与恢复流程）。
```
