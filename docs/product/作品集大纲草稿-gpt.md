# P01｜项目背景（Project Background）

## 页面标题

AI试穿APP《衣橱 EARS》

副标题：  
“让用户在下单前，先看到真实的自己。”

---

## 页面内容

### 1. 行业背景

线上服饰消费持续增长，但“无法真实试穿”始终是核心问题。

用户在电商平台浏览服装时，经常会经历：

- 模特效果很好，但自己穿起来完全不同
    
- 买回后发现不适合，退货率高
    
- 衣服越买越多，却不知道怎么搭配
    

AI视觉生成能力的发展，让“虚拟试穿”开始从概念进入真实消费场景。([ScalaCode](https://www.scalacode.com/case-studies/trystyle-ai-powered-virtual-try-on-fashion-ecommerce/?utm_source=chatgpt.com "TryStyle | AI-Powered Virtual Try-On For Fashion ECommerce"))

### 2. 用户痛点

传统网购服装存在三个核心断层：

|用户行为|真实问题|
|---|---|
|浏览商品|无法建立“穿在我身上”的想象|
|购买决策|缺乏搭配参考，决策焦虑|
|购买之后|衣橱闲置率高|

很多用户并不缺衣服，而是缺“被重新利用的衣服”。


因此，《衣橱 EARS》定位为：

> “AI驱动的个人数字衣橱与试穿助手”

# P02｜用户研究（User Research）

## 页面标题

用户研究：问题不只是“买衣服”

## 页面内容

### 1. 目标用户画像

核心用户：

- 18-35岁女性
    
- 高频线上服饰消费用户
    
- 注重穿搭表达
    
- 有社交分享需求
    
- 经常出现“衣服很多但不会搭”的问题
    
### 2. 关键使用场景

|场景|用户行为|
|---|---|
|网购前|想先确认是否适合自己|
|出门前|不知道今天穿什么|
|换季整理|衣橱混乱，难以管理|
|社交分享|希望获得朋友反馈|

### 3. 深度访谈摘要

访谈了8位目标用户后，发现两个高频现象：

#### 用户A

“收藏夹里很多衣服，但我不敢下单，因为模特和我完全不是一种身材。”

#### 用户B

“每天出门前最耗时间的不是化妆，是翻衣柜。”

#### 用户C

“很多衣服其实没问题，只是我不会搭。”

### 4. 用户旅程与痛点

| 阶段  | 用户心理 | 痛点       |     |     |
| --- | ---- | -------- | --- | --- |

| 决策  | 犹豫   | 害怕踩雷     |     |     |

|     |      |          |     |     |

| 阶段    | 用户行为            | 用户心理          | 痛点              | 产品机会   |
| ----- | --------------- | ------------- | --------------- | ------ |
| 发现衣服  | 在淘宝、小红书、INS浏览穿搭 | “这件好像很好看”     | 模特与自己身材差异大，无法代入 | AI虚拟试穿 |
| 收藏/犹豫 | 加入收藏夹，反复对比      | “我穿会不会显胖？”    | 决策焦虑严重，容易反复横跳   | 真实模特生成 |

AI试穿的本质，是帮助用户建立“自我穿搭认知”。

### 设计重点

#### 1. 降低等待焦虑

- 全屏展示

- 底部悬浮操作栏
    

让用户更像在“照镜子”。

---

#### 3. 减少流失

结果页直接提供：

- 保存衣橱
    
- 再试一件
    
- 搭配其他衣服
    

避免用户操作断层。

# P10｜个人复盘与思考（Reflection）

## 页面标题

项目复盘：AI产品真正难的不是 AI

---

## 页面内容

### 1. 最大挑战

#### 挑战一：结果真实感

用户对“脸”和“身材”极其敏感。

即使AI结果只有轻微变形，也会快速失去信任。

因此：

- 模特上传规范非常重要
    
- 需要增加图片校验机制
    
- 结果页必须支持用户重新尝试
    

---

#### 挑战二：等待体验

AI生成天然存在延迟。

如果只显示“Loading”，用户会迅速流失。

因此增加：

- 情绪化文案
    
- 进度反馈
    
- 超时状态设计
    

---

### 2. 产品思考

我逐渐意识到：

AI产品不是“展示技术”。

而是：

> 用技术解决真实生活里的犹豫和焦虑。

---

### 3. Vibecoding 工作流

本项目采用 Vibecoding 工作流：

```text
用户洞察
→ AI辅助需求整理
→ Figma原型
→ Cursor辅助代码生成
→ 数据埋点设计
→ 体验迭代
```

核心优势：

- 快速验证想法
    
- 缩短原型周期
    
- 提高产品迭代效率
    

---

### 4. 最终收获

这次项目让我真正理解：

优秀的 AI 产品，并不是“炫技”。

而是：

> 让用户觉得“它真的懂我”。
