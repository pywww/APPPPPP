## 一、遇到的主要困难（条目）

1. **环境与预期不符**：本地曾只剩 Vite 欢迎页；浏览器全宽使 H5 像灰底占位，底栏难感知。  
2. **还原度**：目标近 95%，初期偏功能原型，与稿差距大。  
3. **交付不清**：不知抄数抄什么、Token 从哪来；模板项多、负担重。  
4. **权限与工具**：Figma **Starter** 下 **MCP 限额**紧；Dev Mode、Copy as CSS 依赖套餐。  
5. **清单对齐**：交付表与 MVP 比，有**命名易混**、若干流程屏**未在表中单独体现**之风险。

---

## 一点五、困难与「还原度低」的根因分析（展开）

### 1. 工程实现与稿面「不是同一套信息」

- **数值未从稿来**：早期颜色、间距、圆角多来自**占位或组件库默认**，与 Figma 中具体 HEX、px **未建立对应**，肉眼「差不多」在叠图时会放大成系统偏差。  
- **组件皮肤≠设计系统**：**antd-mobile** 等默认 List / Empty / Button 的圆角、字重、行高常与稿不同；若不**覆盖样式或自建块**，整体会像「通用中台」而非定制稿。  
- **资源未入库**：图标、插画、复杂背景若用**占位或纯 CSS** 代替稿中切图，还原上限会被压低（非单靠调 margin 可补）。

### 2. 观看环境与稿面预设不一致

- **桌面全宽 vs 手机画幅**：稿按 **375/390** 宽；宽屏全宽展示时内容**横向拉散**、底栏相对下移，易误判为「没按稿做」，实为**视口与稿宽未对齐**。  
- **未做叠图验收**：无「稿 PNG + 浏览器同宽半透明对齐」则**误差不可量化**，易停在「感觉不像」，难收敛到 95% 口径。

### 3. 流程与协作断层

- **单一真相未统一**：工程、口头与 Figma **各一套数**时，开发优先**可运行**，难与某一帧像素一致；无 **Token / Variables** 则改稿也难全局联动。  
- **交付表与需求未完全同构**：引导、异常恢复、换模特批量重算等若**仅有文字、无可链节点**，实现会**临时补 UI**，与主稿**风格漂移**；命名混淆会导致**链错屏、验错屏**。  
- **源码曾回退**：若工程只剩模板页，看到的是 **Vite 欢迎页**，属**环境与交付物**问题，与设计质量无关。

### 4. 工具权限的硬约束

**Starter + MCP 限额**使 AI **无法稳定读稿**，自动抄数/对照变难，手工切换成本高，细项易被省略；**Dev Mode 受限**时，「按稿」易退化为**凭感觉**，还原度随之下降。

### 5. 「还原度低」的一条因果链（复盘用）

**稿内数字与资产未系统进入代码 → 在错误视口下查看 → 未用叠图量化 → 组件默认样式未覆盖 → 观感与 Figma 差距大。** 逼近 95% 需在链路上逐项打结：Token/切图、手机宽预览、关键块覆盖或自定义、叠图锚点验收。

## 二、方案与优劣势（摘要）

| 方案 | 优 | 劣 |
| --- | --- | --- |
| **按稿 + Token + 叠图** | 以稿为准、可测可签 | 耗时，要画幅与变量规范 |
| **分级验收** | 省工期 | 非核心屏与稿有差，须约定范围 |
| **设计贴 antd-mobile** | 少覆盖样式 | 视觉自由度降 |
| **大块切图** | 快 | 改版/多语言/体积与无障碍差 |
| **导出代码 / MCP** | 少手抄、初稿快 | 须接本栈与 Token，非终稿 |
| **AI 重做 UI** | 可能更整齐 | **双源**，难对齐原 Figma |

---

## 三、综合选择的路径

- **主线**：Figma 单一真相 → **全局 Token 一次 + 单屏差异 + 叠图**；细项用属性全集**按需**补抄。  
- **减负**：`design-handoff/抄数表格模板_全界面.md` **一点五「最小清单」**：全局约 ≤25 行 + **每屏 ≤15 行**，相同则写「同全局」。  
- **工具**：**Professional + Full**（纯对接稿可选 **Dev**）开 Dev Mode；**升 Figma MCP** 在 Cursor 内拉节点/截图/资源，**加速抠数**，不替代 Token 与叠图。  
- **工程**：**手机画幅**（如 `app-shell`）+ `variables.css`，避免桌面拉散。

---

## 四、技巧与经验

- **数值来自 Figma**；**`--xxx` 名**对齐 `h5-demo-react/src/styles/variables.css` 或由开发补，不必在稿里「抄变量名」。  
- **Copy as CSS** 只摘 px/色值进表，勿整段当生产布局。  
- **叠图**：稿 **PNG@2x** + 浏览器 **375 宽**截图，半透明对 **8～12 锚点**。  
- **维护交付表**：补引导/异常/弹窗链接或备注；**序号 19** 在表中写「我的穿搭页」但链到 `Screen/Workshop`，易与「穿搭记录 `Looks`」混淆，**建议改名为「穿搭工坊」或备注清楚**。

---

## 五、注意事项

1. **Figma MCP 限额**看 Figma **套餐/席位**，与 **Cursor 订阅无关**。  
2. 离开 **Starter** 才利于 Dev Mode、Inspect、MCP；**一人设计+落地优先 Full**。  
3. **AI** 无稿则无法代填真抄数；MCP 后仍要**校对+叠图**。  
4. 模板与清单在 **`design-handoff/`**，与 **`Figma链接交付表.md`** 同用。  
5. **Vue / React 两版 Demo** 若共用 IndexedDB 库名，数据会互通；要隔离需在代码中改库名。
